- 문서 버전: v0.2 (D-1~D-3 사용자 확정, 2026-10-13)
- 작성일: 2026-10-13
- 범위: 요구사항 정의만 다룬다. API 실제 동작·요금은 STEP 2(`api-analysis.md`)에서 검증하며, 이 문서에서 **[검증 필요]** 로 표시한 항목은 확인 전까지 사실로 간주하지 않는다.

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | PAW MAP |
| 한 줄 정의 | 현재 위치 또는 검색 지역 주변의 **반려견 동반 가능** 음식점·카페·숙소·관광지를 지도와 목록으로 통합 검색하는 모바일 웹앱(PWA) |
| 대상 사용자 | 반려견과 외식·카페·여행·관광을 계획하는 보호자 |
| 서비스 범위 | 전국 검색 가능하도록 설계. 초기 테스트 지역은 **제주**(설정값으로 분리, §8 D-2) |
| 운영비 목표 | 월 0원 (무료 사용량 안에서 운영, 초과 위험 시 기능을 줄여서라도 과금 차단) |
| 비목표(MVP) | 회원가입·로그인, 리뷰·평점 작성, 실시간 객실 예약·결제, 사용자 위치 저장 |

### 1.1 핵심 원칙

1. **동반 가능으로 오인시키지 않는다.** 확인되지 않은 정보는 `UNKNOWN`, 없는 조건은 "허용"으로 보지 않는다.
2. **출처와 시점을 항상 보여준다.** 모든 반려견 관련 정보에는 데이터 출처와 확인(또는 조회) 날짜를 함께 표시한다.
3. **상충 정보는 확정하지 않는다.** 출처별 정보를 모두 보존·표시하고 사용자가 판단하게 한다.
4. **비용이 기능보다 우선한다.** 유료 호출은 필요한 필드·필요한 순간에만 한다.

## 2. 현재 저장소 검토 결과

현재 디렉터리(`/home/user/NearMe`)는 비어 있지 않고, 이미 운영 중인 **NearMe**(주변 장소·제주 버스·항공·길찾기 시간 앱)가 있다. PAW MAP과 기술 스택이 거의 같아 참고·재사용할 자산이 많다.

| NearMe 자산 | PAW MAP 활용 가능성 |
|---|---|
| React 19 + TS + Vite 7 + Tailwind 4, PWA manifest | 동일 스택. 프로젝트 템플릿으로 재사용 가능 |
| `useGeolocation` 훅, 권한 거부 시 기본 좌표 처리 | FR-001에 그대로 응용 |
| Google Maps(`@vis.gl/react-google-maps`), 마커 클러스터(`utils/cluster.ts`), BottomSheet | FR-005 지도·목록 UI에 응용 |
| Places API(New) Nearby Search를 **필드 최소화**로 호출하는 패턴 | FR-003·비용 통제 패턴으로 응용 |
| FastAPI 백엔드, 메모리 TTL 캐시, data.go.kr 인증키 처리(따옴표 제거 등) | TourAPI 클라이언트에 응용 |
| T map 도보·자동차 소요시간(`/api/routes/eta`) | 상세 화면 이동시간 표시(추후 기능 후보) |

**이미 확인된 배포 사실(NearMe README, 2026-10-12 기록)**
- Cloudflare Python Workers **무료 플랜**에서 FastAPI 실행 시 요청당 CPU 약 10ms 제한으로 `Error 1102` 발생 → NearMe 백엔드는 Google Cloud Run으로 이전했다.
- 따라서 마스터 프롬프트의 "Backend: Cloudflare Workers 우선 검토"는 STEP 3에서 **유료 플랜 여부·대안(Cloud Run, TypeScript Workers 전환 등)** 과 함께 다시 판단해야 한다.

## 3. 누락·모호한 요구사항과 제안

| # | 원 요구사항의 모호점 | 제안(이 문서에 반영한 기본안) |
|---|---|---|
| A-1 | Google Places 결과 대부분은 `allowsDogs` 정보가 없을 가능성이 큼. 그대로 섞으면 목록이 `UNKNOWN`으로 가득 참 | 기본 필터 = **"동반 가능만"**(D-3 확정). "확인 안 됨 포함" 토글로 확장. Google 데이터의 MVP 포함 범위는 STEP 2 비용 검증 후 확정 |
| A-2 | FR-008은 상태를 3개로만 정의, 상충 시 표시 방법이 없음 | 최종 상태는 3개 유지, **출처별 근거(`petEvidence[]`)** 를 별도 보관하고 상충 시 `UNKNOWN` + "출처 간 정보 상충" 배지 표시 |
| A-3 | "정보 확인일"의 정의 없음. Google은 검증일을 주지 않음 | `sourceUpdatedAt`(출처가 제공한 수정일)과 `fetchedAt`(우리가 조회한 시각)을 구분. 화면에는 "관광공사 수정일 2026-08-01" / "Google 조회 2026-10-13"처럼 **의미가 다른 날짜임을 명시** |
| A-4 | "카페" 카테고리: TourAPI가 카페를 음식점 유형에 포함할 가능성 **[검증 필요]** | 출처 분류 → PAW MAP 카테고리 매핑 규칙을 STEP 2에서 정의. 판별 불가 시 음식점으로 분류 |
| A-5 | 10km 반경 + Google Nearby Search 결과 상한(20건 **[검증 필요]**) → 넓은 반경에서 누락 | 결과가 상한에 도달하면 "결과가 많아 일부만 표시됩니다. 지도를 확대해 다시 검색하세요" 안내 |
| A-6 | 복수 카테고리 선택 = 카테고리 수만큼 API 호출 → 비용 증가 | 카테고리당 1회 호출을 원칙으로, Google 호출은 사용자 수동 검색 시에만(지도 이동 자동검색 금지) |
| A-7 | 지역명 검색에 쓸 지오코딩 API 미정(Google Geocoding / Places Text Search / 카카오 로컬 등) | STEP 2에서 무료 한도·정확도 비교 후 선택 |
| A-8 | 캐싱·저장 가능 범위가 출처마다 다름(Google 약관상 대부분 캐싱 제한, 공공데이터는 이용조건 유형별 상이) **[검증 필요]** | 약관 확인 전까지 **영구 저장 금지**, 메모리 단기 캐시만 허용. 확인 후 출처별 캐시 정책표 작성 |
| A-9 | 이미지 사용 조건(공공누리 유형, Google Photos 귀속 표시·과금) 미정 | 출처별 이미지 표시 조건을 STEP 2에서 확인. 미확인 시 이미지 대신 카테고리 아이콘 표시 |
| A-10 | 초기 테스트 지역 미정 | **제주**(D-2 확정). 설정값 `DEFAULT_REGION`으로 분리 |
| A-11 | 정보 오류 신고 기능 없음 | 추후 기능(Phase 2)으로 분류. MVP는 "정보가 다를 수 있으니 방문 전 업체에 확인하세요" 고지 + 전화 버튼 |
| A-12 | 저장소 위치 미정(NearMe 저장소 내부 vs 신규 저장소) | **신규 저장소 `paw-map`**(D-1 확정) |

## 4. 기능 요구사항

우선순위: **M** = MVP 필수, **S** = MVP 포함 권장(일정 여유 시), **L** = 추후(Phase 2 이후)

### FR-001. 현재 위치 조회 — M

- 브라우저 Geolocation API로 위도·경도를 얻는다. 권한 요청은 **사용자가 "현재 위치" 버튼을 누르거나 첫 진입 안내에 동의할 때**만 한다.
- 권한 거부·시간 초과·미지원 시 `DEFAULT_REGION` 중심으로 지도를 띄우고 지역 검색을 안내한다.
- 위치 좌표는 검색 요청에만 사용하고 서버·로그에 저장하지 않는다(로그에는 소수점 2자리 이하로만, 또는 기록하지 않음).

**수용 기준**
- 권한 허용 → 3초 이내 현재 위치 마커 표시 후 자동 검색 1회
- 권한 거부 → 오류 대신 안내 문구 + 기본 지역 지도, 모든 기능 사용 가능
- HTTPS 환경에서만 동작함을 전제(로컬 `localhost` 예외)

### FR-002. 지역 검색 — M

- 검색창에 지역명·주소·관광지명을 입력하면 좌표로 변환해 지도 중심을 이동하고 검색한다.
- 결과가 여러 개면 후보 목록(최대 5개)을 보여주고 선택하게 한다.
- 결과 없음·API 오류 시 안내 문구를 표시한다.
- 사용 API는 STEP 2에서 결정(A-7). 입력 디바운스 없이 **검색 버튼/Enter 시에만** 호출(자동완성은 비용 문제로 L).

### FR-003. 통합 카테고리 검색 — M

| PAW MAP 카테고리 | 코드 | 비고 |
|---|---|---|
| 음식점 | `RESTAURANT` | |
| 카페 | `CAFE` | 매핑 규칙 A-4 |
| 숙소 | `STAY` | 세부 유형 FR-010 |
| 관광지 | `ATTRACTION` | 공원·해변 등 포함 여부 STEP 2에서 확정 |

- 단일·복수 선택 가능. 기본값은 4개 전체 선택.
- 백엔드는 선택 카테고리를 받아 출처별로 조회 → 정규화 → 중복 제거 → 반경 필터 → 정렬 후 반환한다.

### FR-004. 검색 반경 — M

- 1km / 3km(기본) / 5km / 10km.
- 출처 API가 반경 검색을 하더라도 **서버에서 하버사인 거리로 다시 필터링**해 반경 밖 결과를 제거한다.
- 결과 상한 도달 시 A-5 안내.

### FR-005. 지도 기반 검색 — M

- 지도, 현재 위치 마커, 카테고리별 색·아이콘 마커, 겹치는 마커 묶음 표시.
- 마커 탭 → 요약 카드(이름·카테고리·거리·동반 상태). 카드 탭 → 상세.
- 지도를 일정 거리 이상 움직이면 "이 지역 검색" 버튼 노출. **자동 재검색은 하지 않는다**(비용).
- 목록 항목 선택 ↔ 지도 마커 강조 연동.
- 지도 SDK(Google Maps JS / 카카오맵 등)는 STEP 2 비용 비교 후 확정.

### FR-006. 장소 목록 — M

카드 표시 항목: 장소명, 카테고리, 주소, 검색 중심으로부터 거리, 대표 이미지(조건 충족 시, A-9), 반려견 동반 상태 배지, 동반 조건 요약(있을 때만), 데이터 출처, 정보 날짜(A-3).

- 정렬: 거리순(기본). 추후 이름순 등은 L.
- 필터: 동반 상태 = "동반 가능만"(기본) / "확인 안 됨 포함" / 전체(동반 불가 포함).
- 빈 결과: 반경 확대·카테고리 변경 제안 문구.

### FR-007. 장소 상세 정보 — M

- 장소명, 주소(복사 버튼), 전화번호(`tel:` 링크), 위치 미니맵, 영업시간(제공 시), 대표 사진, 동반 여부·조건 전체, 출처별 근거와 날짜, 홈페이지/예약 링크(제공 시).
- 외부 길찾기: 네이버지도·카카오맵 링크(앱 스킴 + 웹 대체 URL). URL 형식은 STEP 2에서 확인.
- 상세 진입 시 추가 API 호출이 필요한 경우(예: Google Place Details) 비용 SKU를 STEP 2에서 확인하고, 유료라면 **상세 화면 진입 시 1회만** 호출한다.
- 상세는 URL(`/place/{source}:{id}`)로 접근 가능하게 하여 공유·뒤로가기를 지원한다 — S.

### FR-008. 반려견 동반 상태 관리 — M

- 최종 상태: `ALLOWED` / `NOT_ALLOWED` / `UNKNOWN`.
- 결정 규칙
  1. 근거가 하나도 없으면 `UNKNOWN`.
  2. 모든 근거가 같은 값이면 그 값.
  3. 근거끼리 다르면 `UNKNOWN` + `hasConflict = true` (임의 확정 금지).
- 출처별 근거는 `petEvidence[]`에 출처·값·날짜·원문 요약을 보관해 상세 화면에 모두 표시한다.

### FR-009. 반려견 동반 조건 — 모델은 M, 필터 UI는 L

- 데이터 모델에 크기별 허용, 최대 마릿수, 실내/실외, 목줄·이동장 필수, 추가 요금, 기타 제한을 둔다.
- 값이 없으면 `undefined`(= 확인 안 됨). **화면과 필터에서 허용으로 취급하지 않는다.**
- 출처 원문이 자유 텍스트이면 원문을 그대로 `notes`에 보관·표시하고, 구조화 파싱은 신뢰도가 확인된 필드만 한다.
- 크기·실내 등 조건 필터 UI는 STEP 2에서 실제 데이터 충족률을 본 뒤 결정(L).

### FR-010. 숙소 전용 조건 — 표시는 S, 필터는 L

- 숙소 유형: 호텔, 펜션, 리조트, 풀빌라, 캠핑장, 글램핑, 기타.
- 부가 정보: 반려견 운동장, 개별 울타리, 반려견 추가 요금.
- MVP는 출처가 제공하는 범위에서 상세 화면에 표시만 한다. 예약은 외부 링크로 연결(결제·객실 조회 없음).

### 추후 기능 후보(L)

- 조건 필터(소형/중형/대형, 실내 동반), 숙소 유형 필터
- 즐겨찾기(기기 로컬 저장), 최근 검색
- 정보 오류 신고, 사용자 제보
- 도보·자동차 소요시간(NearMe T map 연동 재사용)
- 검색어 자동완성, 다국어

## 5. 데이터 모델 (초안)

마스터 프롬프트의 `PetPlace`를 기반으로 A-2·A-3을 반영했다. 최종본은 STEP 3에서 실제 API 응답을 보고 확정한다.

```ts
type PetStatus = 'ALLOWED' | 'NOT_ALLOWED' | 'UNKNOWN'
type PlaceCategory = 'RESTAURANT' | 'CAFE' | 'STAY' | 'ATTRACTION'
type DataSource = 'KTO_TOURAPI' | 'GOOGLE_PLACES'
type StayType = 'HOTEL' | 'PENSION' | 'RESORT' | 'POOL_VILLA' | 'CAMPING' | 'GLAMPING' | 'OTHER'

interface PetEvidence {
  source: DataSource
  status: PetStatus          // 이 출처가 말하는 값
  sourceUpdatedAt?: string   // 출처가 제공한 수정일(ISO 8601)
  fetchedAt: string          // 우리가 조회한 시각
  rawText?: string           // 출처 원문(조건 설명 등)
}

interface PetConditions {    // undefined = 확인 안 됨(허용 아님)
  smallDogsAllowed?: boolean
  mediumDogsAllowed?: boolean
  largeDogsAllowed?: boolean
  maxDogs?: number
  indoorAllowed?: boolean
  outdoorAllowed?: boolean
  leashRequired?: boolean
  carrierRequired?: boolean
  additionalFee?: number     // 원. 금액 불명확 시 undefined + notes
  notes?: string[]           // 구조화 못 한 원문
}

interface StayInfo {
  stayType?: StayType
  hasDogPlayground?: boolean
  hasPrivateFence?: boolean
}

interface PetPlace {
  id: string                 // `${source}:${sourceId}` 또는 병합 시 대표 ID
  sourceIds: Partial<Record<DataSource, string>>
  name: string
  category: PlaceCategory
  latitude: number
  longitude: number
  address?: string
  phone?: string
  imageUrl?: string
  imageAttribution?: string
  homepageUrl?: string
  openingHours?: string[]
  distanceMeters?: number
  petStatus: PetStatus       // FR-008 규칙으로 계산된 최종값
  hasConflict: boolean
  petEvidence: PetEvidence[]
  petConditions?: PetConditions
  stayInfo?: StayInfo        // category === 'STAY'일 때만
  sources: DataSource[]
}
```

### 5.1 중복 제거 규칙(초안)

같은 장소로 판정하려면 다음을 **모두** 만족해야 한다. 하나라도 불확실하면 병합하지 않고 별개로 표시한다.

1. 좌표 거리 ≤ 50m (임계값은 STEP 6 테스트로 조정)
2. 그리고 다음 중 하나 이상: 정규화 전화번호 일치 / 정규화 도로명 주소 일치 / 정규화 이름 일치(공백·괄호·지점명 처리)
3. 이름 유사도만으로는 병합하지 않는다.
